# embedded_systems_design

基于 STM32F746G-DISCO 的双板声学测距工程。两块板识别同一次 50 ms chirp 或拍手，交换到达时刻（TOA），用到达时间差和触发时温度对应的声速计算声程差。

| 工程 | 角色 | 默认 IP | IAR 工作区 | 已编译固件 |
| --- | --- | --- | --- | --- |
| [Board_A](Board_A/) | 主板、同步基准，采集 DHT11 温度并向 B 板发送温度和声速 | `192.168.1.10` | [Board_A/EWARM/Project.eww](Board_A/EWARM/Project.eww) | [LT_KeShe.hex](Board_A/Firmware/LT_KeShe.hex) |
| [Board_B](Board_B/) | 从板，根据同步结果修正时钟，接收 A 板温度和声速 | `192.168.1.11` | [Board_B/EWARM/Project.eww](Board_B/EWARM/Project.eww) | [LT_KeShe_B.hex](Board_B/Firmware/LT_KeShe_B.hex) |

## 下载、编译和连接

在 GitHub 仓库选择 **Code → Download ZIP**，解压整个压缩包并保留两套工程的目录结构。也可以克隆仓库。每套工程包含 IAR 工程和调试配置、启动和链接文件、CubeMX `.ioc`、应用源码、STM32 驱动、LwIP 和 FreeRTOS。构建时 IAR 会生成本机中间文件。两板各自的 `Firmware` 目录附有本版本可烧录的 HEX。

1. 用 IAR Embedded Workbench for Arm **9.40.1** 分别打开上表的两套 `EWARM/Project.eww` 工作区，选择项目配置 `LT_KeShe` 或 `LT_KeShe_B`，编译后烧录到对应板卡。
2. 两板通过以太网互通。默认子网掩码为 `255.255.255.0`，同步和测距报文使用 UDP `5000`。
3. 两板麦克风模块的模拟输出接各自的 **PA0（ADC3_IN0）**，模块与本板共地。A 板 DHT11 的 DATA 接 **PB4**，与 A 板共地。
4. 等两板时钟收敛后，播放与内置模板匹配的 chirp，或在一侧拍手。测两麦克风间距时，将声源放在两麦克风连线的外侧，按“声源 → A 板 → B 板”或镜像顺序共线摆放。屏幕的 `CHIRP cm` 和 `CLAP cm` 分别显示相应声源的声程差，在这种布置下等于两麦克风间距。

## 声音识别参数

| 参数 | A 板 | B 板 | 作用 |
| --- | --- | --- | --- |
| `MIC_CHIRP_MIN_R` | `0.22f` | `0.22f` | 本地 chirp 识别的归一化相关门限 |
| `MIC_CHIRP_PEER_MIN_R` | `0.13f` | `0.13f` | 对端报文引导回查时的相关门限 |
| `MIC_TDOA_VALID_US` | `7353 µs` | `7353 µs` | 两板到达时刻允许的最大绝对差 |
| 包络触发下限 | 16 个 ADC 码 | 9 个 ADC 码 | 自适应触发门限的最低值 |
| `MIC_TRIG_CONFIRM` | 64 点 | 16 点 | 标准音频包络必须连续越限的点数 |

两板都使用 48 点滑动平均和 `max(nfar + 4, npk + 2, 本板下限)`。触发后对同一段采样分别做 chirp 相关和拍手瞬态识别，再发布唯一类别。拍手识别参数位于两板的 `Core/Inc/mic_clap.h`。

TOA 报文以 `t2=1` 标记 chirp、`t2=2` 标记拍手。两板应成对更新固件。同类事件且原始时间差不超过 7353 µs 才可配对，两类结果分别保存历史和标准差。明确换侧时，若校准后时差的符号相反且前后幅值均达到门限（chirp 100 µs，拍手 400 µs），第一个有效配对即可更新方向；同侧大跳变仍需连续三个相互接近的候选确认。

任一板先识别出标准音频，另一板收到 TOA 报文后可在本地约 0.5 s 的采样缓存中回查。若本地候选与对端时刻相差超过 7353 µs，系统保留报文供回查，结合相关峰和分段一致性重新寻找直达声。标准音频的时差校准由屏幕上的 `CAL` 菜单控制。

参数位于 [A 板 mic.c](Board_A/Core/Src/mic.c) 和 [B 板 mic.c](Board_B/Core/Src/mic.c)。`Core/Src/freertos.c` 负责时钟同步和 TOA 报文，`Core/Src/disp.c` 负责触摸菜单、声速选择和测量结果显示，`LWIP/App/lwip.c` 设置本板地址。串口 USART1 为 115200 baud，`tg` 是包络触发次数，`ev` 是通过识别并发布的事件数，`rx` 是收到的对端 TOA 报文数，`pr` 是本板成功配对并接受的次数。`[PEER]` 行中的 `attempts`、`history_gap`、`accepted` 和 `far` 分别记录回查尝试、缓存缺段、回查接受和超限拒绝次数。

## 温度模式与距离记录

点击屏幕左上角温度区域，进入 `TEMP MODE`。

- `DHT11 AUTO` 使用 A 板 DHT11 的有效读数，A 板通过 PB4 采集，B 板通过网络接收。
- `SET TEMP` 打开手动档位，从 −20、0、20、40、60 °C 中选择。

在任一板上切换温度模式或选定手动档位，另一板会通过同步报文采用相同设置。屏幕的 `C … m/s` 一栏显示当前用于新测量的声速。

包络触发时记录当时所选声速。声纹识别和 TOA 配对成功后，用该声速与校准时差计算并保存距离，最近十条记录和累计标准差使用各次保存的距离。若自动模式在触发时没有有效温度，声音识别和配对仍正常进行，该次距离显示为 `--`，不计入距离 SD。温度刷新或切换模式只影响之后触发的事件。


## 标准音频触摸校准

点屏幕顶部温度区域右边的 `CAL`，用 `+`、`−` 调整 `A-B BIAS` 和 `RANGE BIAS`，每次调整 1 µs，范围为 −100 至 +100 µs。点 `APPLY` 应用并同步到另一板，或点 `CANCEL` 放弃本次修改。两个屏幕采用相同的 A 减 B 符号约定，B 板计算本板时差时会将第一项反号。

- 两项同加 1 µs 时，声源在 A 板一侧的距离保持原样，B 板一侧用于测距的时差幅值减少 2 µs。两项同减 1 µs 时，B 板一侧的时差幅值增加 2 µs。该关系适用于声源方向判定保持不变的外侧测量。
- 应用新值后，标准音频的历史和标准差从下一笔配对重新统计。拍手使用独立的记录和统计。
- 两板都重新上电后使用固件默认值，屏幕显示 `A-B BIAS = +12 µs`、`RANGE BIAS = +30 µs`。固件中 A 板的本地偏差为 +12 µs，B 板为 −12 µs。单板重启后可从仍在运行的对端恢复校准值。

## 标准差和测量质量

- `CLAP SD` 统计当前距离的拍手样本，`CHIRP SD` 统计当前距离的标准音频样本。两类样本独立累计。当前类别不足两个有效距离样本时，标准差显示为 `--`。
- 系统确认当前类别测到了新距离后，从该类别的新距离样本开始重新统计。另一类别保留自己的测量记录。
- 串口 `[QUAL]` 每次输出已接受配对的类别、距离 `dist`、方向 `dir` 和质量指标。`n` 表示当前类别的标准差样本数，`reset 1` 表示当前类别已确认新距离。
